## Errors and acceptance gaps

1. **Expired registry credentials:** the first candidate Pod entered `ImagePullBackOff` with `403 Forbidden: Your authorization token has expired` through the existing shared pull Secret. The isolated `aip5401-ecr-pull` Secret resolved the candidate pull. This is an environment error, not evidence that the supplied image is unavailable.
2. **CPU-only startup contract mismatch:** the supplied image failed without `PLATFORM_URL` even though the LAS draft identifies `AGENT_SERVER_URL` as the required LAS endpoint. The isolated fixture uses an unreachable loopback URL to start the image. Product code should remove the unused model URL requirement for a LAS-only profile or specify its supported CPU-only value. Model-serving calls through this fixture cannot succeed.
3. **Assistant ID contract blocker:** the supplied image sends `aitier:<agent_name>` as `assistant_id` to `POST /assistants`. LAS version `0.15.1` rejected that value with HTTP 422, `Invalid assistant ID: must be a UUID`; SLIM masked it as HTTP 400 with an internal-server-error message. No intended-caller create can pass with this image and LAS contract.
4. **Thread ID contract blocker and error propagation:** even with a directly created UUID assistant, the image called `/threads/validation:<session_id>/runs/wait`. LAS logged `invalid thread ID; invalid UUID format` and returned HTTP 500. SLIM's response was HTTP 200 with a final NDJSON object carrying `success=false` and `http_error_code="500"`. AIP-5401's successful route and error-response criteria are unmet.
5. **Authorized caller passes identity checks but has no demonstrated production grant:** the in-cluster Splunk admin interactive JWT passed the image's issuer/JWKS and current-context checks, and authenticated create/invoke reached the LAS adapter. Both missing-bearer routes and a malformed-bearer create were denied. The deployed CMP authorization path does not inspect a route-specific role, scope, or caller grant, and the test did not include a non-admin or actual AITK principal. Do not infer that `ENABLE_AUTHN=false` or `ENABLE_AUTHZ=false` bypasses this route; it always applies the authorizer dependency. The ID blockers prevent a successful graph result even for the authenticated admin caller.
6. **Product clarification on response mode:** incremental LAS events are not required for this agent image; the product path requires the final response only. The failed-run diagnostic produced a terminal NDJSON object but no successful final result, so route acceptance remains blocked by the assistant/thread UUID contract mismatch. The strict `PLATFORM_URL` startup requirement is also pending the developer's planned modification; this fixture used an unreachable loopback placeholder.
7. **Graph/input fixture mismatch:** this cluster's `echo` sample graph expects `state["request"]`, while the supplied SLIM route builds `input.messages` and `system_prompt`. The ID failures occurred before graph execution, so this additional mismatch was not resolved by testing. A compatible product graph or adapted fixture is needed for meaningful result and persisted-state checks after the ID contract is fixed.
8. **No operator-owned deployment check:** the current shared operator was intentionally left at its original digest and no primary SLIM AIService update was made. The isolated manifest verifies the candidate image, LAS Service reachability, denial, and adapter failures. It does not establish operator reconciliation, automatic rollout, or production configuration on the existing SLIM workload.
9. **Transport/access boundary:** the fixture and LAS Services are internal `ClusterIP` over HTTP. No public ingress was added. The namespace has no `NetworkPolicy`, so no network-level egress or pod-to-pod restriction was established. TLS/mTLS and a real external product caller were not exercised. Those are explicit limitations under AIP-5403's ingress/transport/egress criterion.
