# AIP-5408 live egress acceptance evidence

Captured 2026-10-22 from the installer cluster in namespace `ai-platform`.
The test used a temporary NetworkPolicy generated by
`tools/cluster_setup/las_deployment.py`; no source configuration or LAS
Deployment was changed. The policy was deleted after the checks, and the
temporary SSH ingress rule was revoked.

## Workload and policy

- LAS Helm release: `las-agentruntime-dev-ai-p-eb88ba0f`.
- API Deployment: `las-agentruntime-dev-ai-p-eb88ba0f-langgraph-cloud-api-server`.
- Queue Deployment: `las-agentruntime-dev-ai-p-eb88ba0f-langgraph-cloud-queue`.
- Both Deployments were 1/1 ready before and after the checks. The AIService
  `agentruntime-dev-ai-platform-slim` remained `Ready=True`.
- The generated policy was `las-egress-fc24b9cf38b43872`. It selected only
  this release's API and queue Pods, allowed cluster Pod traffic and CoreDNS,
  and allowed external dependency IP `10.0.35.244/32`.
- The installer's current `cluster-config.yaml` omitted
  `cluster.egress.allowedIPs`, and the namespace had no pre-existing
  NetworkPolicies. To isolate the data-plane behavior, the generated policy
  was applied temporarily with `kubectl`; no installer run or config edit was
  performed.

## Connectivity results from both LAS workloads

| Probe | Before policy | Policy active | After policy deletion |
| --- | --- | --- | --- |
| PostgreSQL `10.0.35.244:5432` | Connected | Connected | Connected |
| Redis `10.0.35.244:6379` | Connected | Connected | Connected |
| `kubernetes.default.svc.cluster.local` DNS | Resolved | Resolved | Resolved |
| External control `1.1.1.1:443` | Connected | Timed out / blocked | Connected |

The same results were observed from both the API and queue Pods. This confirms
that the allowlist policy enforces the configured external destination while
retaining database, Redis, and cluster DNS connectivity. Deleting the managed
policy restored the cluster's prior omitted-list behavior, including public
egress.
